// ❌ BAD\n\n# Never commit .env file\ngit add .env  # ❌ BAD - will violate .gitignore\n\n# Never share keys via Slack, email, or chat\n# Always use Vercel Secrets Dashboard\n```\n\n### .gitignore Protection\n\nThe `.gitignore` file already protects:\n- `.env*` - All environment files\n- `.env.*.local` - Environment-specific files\n- Private keys (`.pem`, `.key`, `.crt`)\n- Build artifacts (`dist/`, `node_modules/`)\n- IDE files (`.vscode/`, `.idea/`)\n- Logs and temp files\n\n**Verify git is protecting secrets:**\n```bash\n# Check for accidentally committed secrets\ngit log --all --full-history -- \"*.env\"\n\n# If found, use git-filter-branch to remove\ngit filter-branch --tree-filter 'rm -f .env' -- --all\ngit push origin --force --all  # Dangerous - coordinate with team\n```\n\n---\n\n## API Security\n\n### POST /api/deity-image Endpoint\n\n**Implemented Protections:**\n\n1. **Rate Limiting** ✅\n   - 100 requests per 15 minutes per IP\n   - Automatic cleanup of expired limits\n   - Returns 429 (Too Many Requests) when exceeded\n\n2. **Input Validation** ✅\n   - `imageUrl` must be string type\n   - Must start with `data:image/`\n   - Max file size: 5MB\n   - Base64 format validation\n\n3. **Output Safety** ✅\n   - No sensitive paths revealed\n   - Error messages are generic\n   - Stack traces not exposed to client\n\n**Example Attack Prevention:**\n\n```typescript\n// Attack: Try to upload 100MB file\n// Protection: 5MB limit enforced\nPOST /api/deity-image\n{\n  \"imageUrl\": \"data:image/jpeg;base64,<100MB base64>...\"\n}\n// Response: 400 Bad Request\n// \"Invalid image format or exceeds 5MB limit\"\n\n// Attack: Rapid requests to DoS endpoint\n// Protection: Rate limiting\nfor (let i = 0; i < 200; i++) {\n  fetch('/api/deity-image', { method: 'POST', ... })\n}\n// After 100 requests: 429 Too Many Requests\n\n// Attack: Path traversal via file operations\n// Protection: Path sanitization + only public/ directory\n// Even if attacker somehow passes \"../sensitive.txt\"\n// The path.normalize() and validation prevents escape\n```\n\n---\n\n## Input Validation\n\n### Validation Chain\n\n```\nRequest Body\n    ↓\n[1] Type Check (is string?)\n    ↓\n[2] Format Check (starts with data:image/?)\n    ↓\n[3] Size Check (≤ 5MB?)\n    ↓\n[4] Path Check (no traversal?)\n    ↓\nAccepted ✅\n```\n\n### Code Example\n\n```typescript\n// Line 1: Is it a string?\nif (!imageUrl || typeof imageUrl !== \"string\") {\n  return 400; // Invalid\n}\n\n// Line 2: Is it base64 image format?\nif (!isValidBase64Image(imageUrl)) {\n  return 400; // Invalid\n}\n\n// Line 3: File size check inside isValidBase64Image()\nconst maxSize = 5 * 1024 * 1024; // 5MB\nreturn Buffer.byteLength(dataUrl, \"utf8\") <= maxSize;\n```\n\n---\n\n## Rate Limiting\n\n### How It Works\n\n```typescript\nconst requestCounts = new Map<string, { count: number; resetTime: number }>();\n\n// On each request:\n// 1. Get client IP\n// 2. Check if window (15 min) has expired\n// 3. If new window: reset count to 0\n// 4. If within window: increment count\n// 5. If count >= 100: return 429\n// 6. Cleanup expired entries every 5 minutes\n```\n\n### Testing Rate Limiting\n\n```bash\n# Make 101 rapid requests\nfor i in {1..101}; do\n  curl -X POST http://localhost:3000/api/deity-image \\\n    -H \"Content-Type: application/json\" \\\n    -d '{\"imageUrl\": \"data:image/jpeg;base64,iVBORw0K...\"}'\ndone\n\n# First 100 requests: 200 OK\n# Request 101: 429 Too Many Requests\n# Wait 15 minutes for reset\n```\n\n### Why In-Memory Rate Limiting?\n\n- ✅ **Fast**: No database lookup\n- ✅ **Simple**: Easy to understand\n- ✅ **Sufficient**: Works for single-server deployment\n- ❌ **Limitation**: Resets on server restart\n\n**For Production with Multiple Servers:**\nConsider Redis-based rate limiting:\n```bash\nnpm install redis express-rate-limit-redis\n```\n\n---\n\n## Security Headers\n\n### Implemented Headers\n\n```typescript\n// Prevents MIME type sniffing (XSS attack)\nres.setHeader(\"X-Content-Type-Options\", \"nosniff\");\n\n// Prevents clickjacking attacks\nres.setHeader(\"X-Frame-Options\", \"DENY\");\n\n// Enables XSS protection in older browsers\nres.setHeader(\"X-XSS-Protection\", \"1; mode=block\");\n\n// Forces HTTPS (1 year)\nres.setHeader(\"Strict-Transport-Security\", \"max-age=31536000; includeSubDomains\");\n```\n\n### Verify Headers\n\n```bash\n# Check headers on live site\ncurl -I https://sri-varahi-amma-real-estate.vercel.app\n\n# Output should include:\n# X-Content-Type-Options: nosniff\n# X-Frame-Options: DENY\n# X-XSS-Protection: 1; mode=block\n# Strict-Transport-Security: max-age=31536000; includeSubDomains\n```\n\n### Future: Add More Headers\n\n```typescript\n// Content Security Policy (prevents XSS)\nres.setHeader(\n  \"Content-Security-Policy\",\n  \"default-src 'self'; script-src 'self' 'unsafe-inline'\"\n);\n\n// Prevent CORS\nres.setHeader(\"Cross-Origin-Opener-Policy\", \"same-origin\");\n```\n\n---\n\n## Error Handling\n\n### Generic Error Messages\n\n**✅ DO (Safe):**\n```json\n{\n  \"error\": \"Invalid image format or exceeds 5MB limit\"\n}\n```\n\n**❌ DON'T (Dangerous):**\n```json\n{\n  \"error\": \"Error at fs.writeFileSync: /home/app/public/deity.jpg: Permission denied\",\n  \"stack\": \"at writeFile (fs.js:1234:56)...\"\n}\n```\n\n### Why Generic Messages?\n\nAttackers can use error messages to:\n- Discover file paths\n- Find installed libraries\n- Identify server OS\n- Plan targeted attacks\n\n### Error Logging\n\nDetailed errors are logged server-side (safe):\n```\n[2026-09-03T10:45:06Z] ❌ Failed to persist deity image to disk: Error: EACCES: permission denied\n[SECURITY] DISK_WRITE_ERROR {\"error\": \"Error: EACCES: permission denied\"}\n```\n\nClients see only:\n```json\n{\n  \"error\": \"Failed to persist image to disk\"\n}\n```\n\n---\n\n## Logging & Monitoring\n\n### Security Events Logged\n\n```\n[SECURITY] INVALID_DEITY_IMAGE_REQUEST\n[SECURITY] INVALID_DEITY_IMAGE_FORMAT\n[SECURITY] DEITY_IMAGE_UPLOADED\n[SECURITY] DISK_WRITE_ERROR\n[SECURITY] UNHANDLED_ERROR\n[SECURITY] UNHANDLED_REJECTION\n[SECURITY] UNCAUGHT_EXCEPTION\n[Rate Limit] IP 192.168.1.100 exceeded limit\n```\n\n### Monitoring Best Practices\n\n1. **Log All API Requests**\n   ```\n   [timestamp] METHOD path\n   [2026-09-03T10:45:06Z] POST /api/deity-image\n   ```\n\n2. **Track Failed Validations**\n   - Count by error type\n   - Alert if spike (possible attack)\n\n3. **Monitor Rate Limits**\n   - Track IP addresses hitting limits\n   - Flag repeat offenders\n\n4. **Use Log Aggregation**\n   ```bash\n   # For production, use:\n   # - Vercel Logs\n   # - Google Cloud Logging\n   # - Datadog\n   # - New Relic\n   ```\n\n---\n\n## Deployment Security\n\n### Vercel Deployment\n\n#### Step 1: Add Secrets\n\n1. Revoke old key in Google Cloud Console\n   # 2. Create new API key\n   # 3. Add new key to Vercel secrets\n   ```\n\n2. **Update Vercel**\n   - Dashboard → Project Settings → Environment Variables\n   - Update GEMINI_API_KEY\n   - Trigger redeploy\n\n3. **Verify**\n   ```bash\n   # Check new key is deployed\n   vercel logs\n   # Should see new startup timestamp\n   ```\n\n### If Rate Limit is Being Exploited\n\n1. **Check Logs**\n   ```\n   [Rate Limit] IP 203.0.113.42 exceeded limit\n   ```\n\n2. **Identify Pattern**\n   - Is it one IP or distributed?\n   - What time did it start?\n   - How many requests?\n\n3. **Respond**\n   - If one IP: Block via firewall\n   - If distributed: Increase rate limit temporarily\n   - Contact Vercel support if DDoS suspected\n\n### If Unauthorized File Upload Detected\n\n1. **Stop the Service**\n   ```bash\n   vercel remove  # Temporarily remove deployment\n   ```\n\n2. **Investigate**\n   ```bash\n   # Check file system for suspicious files\n   ls -la public/\n   # Check logs for upload events\n   vercel logs\n   ```\n\n3. **Restore**\n   ```bash\n   # Deploy clean version\n   vercel deploy --prod\n   ```\n\n---\n\n## Security Checklist\n\n### Before Going Live\n\n- [ ] All environment variables set in Vercel\n- [ ] API keys marked as \"Sensitive\" in Vercel\n- [ ] `.env*` files in `.gitignore`\n- [ ] HTTPS enforced (Vercel does this)\n- [ ] Security headers enabled (checked)\n- [ ] Rate limiting active (100 req/15min)\n- [ ] Input validation working (tested)\n- [ ] Error messages are generic\n- [ ] Logging is enabled\n- [ ] Graceful shutdown configured\n- [ ] No secrets in git history\n- [ ] No debug mode in production\n\n### Weekly Security Review\n\n- [ ] Check Vercel logs for errors\n- [ ] Review rate limit logs\n- [ ] Check for validation failures\n- [ ] Monitor API response times\n- [ ] Verify backups are working\n- [ ] Update dependencies: `npm audit`\n\n### Monthly Security Review\n\n- [ ] Rotate API keys\n- [ ] Review access logs\n- [ ] Check for security patches\n- [ ] Test disaster recovery\n- [ ] Review incident reports\n- [ ] Update security documentation\n\n---\n\n## Contact & Support\n\n**Security Issues:**\nDO NOT create public GitHub issues for security vulnerabilities.\n\n📧 Email: security@srivarahiammarealestate.com\n\n**Responsible Disclosure:**\nPlease allow 7 days for us to respond to security reports.\n\n---\n\n**Last Updated:** September 3, 2026\n**Version:** 1.0\n"
